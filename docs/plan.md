# Apeiron execution plan

This file owns Apeiron's execution order: the rungs, their tasks, gates and controls, and the board
rows that track them. The programme thesis is in [direction](direction.md); layer ownership and the
trust boundary are in [kernel-boundary](kernel-boundary.md). Where this file disagrees with the source
or a gate, the source and the gate win.

Current performance is in [`docs/evidence/perf-predictions.md` § Current](evidence/perf-predictions.md#current).
That section is the only performance record; this plan cites it and records no competing number.

The previous plan (hash-table ladder L0–L3, inference track, learning track) is
`git show 2f15d6a9:docs/plan.md`. Its receipts stay under `docs/evidence/`; nothing here re-grades them.

## Outcome

Qwen 3.8 27B at **1.18 bits/weight** with llama.cpp 4-bit quality, inside **≤ 4 GB VRAM**, computed
by one composable crate whose every executed primitive is extracted from the real Rust by Aeneas and
refined in Lean (owner, 2026-10-15). The first quality gate is Qwen2.5-0.5B at ≤ 1.18 b/w against
llama.cpp Q4_K_M on the same run (Q4_K_M: 91.37% top-1 agreement, KL 0.0197 nats/token to the f16
teacher).

share a file serialize in the order listed. Every task closes on its gate and its negative control.

## Stop points

- A task owns at most three files, one gate and one negative control; a lane returns its artifact,
  gate output and decision, and the lead re-runs the gate on the live tree before committing.
- No speed or quality lane on a primitive whose F3 row is not green.
- A grade names the extracted body it covers; "proved" is never said of the model.
- No refinement claim about the generic `Table` counts toward `FORM-TABLE`.
- No push to a public remote without the owner's confirmation.
