## Pattern

- Dispatch removal or dispatch-tail removal is the recurring kept CPU win: CPU-02, CPU-03, CPU-05, CPU-08, CPU-11, CPU-12 all relieve `launches` or `chain-depth`.
- Integer-instruction or word-width reductions give the smaller CPU wins: CPU-06, CPU-09, CPU-10, CPU-13, CPU-14 each move one instr/weight field 1.04-1.40x.
- Every refuted CPU scheduling move tests a resource that did not bind: CPU-19, CPU-22, CPU-23, CPU-24, CPU-25, CPU-26 all sit at 0.97-1.03x.
- The one large CPU port outranks every later instruction cut: CPU-01 (4.2x) against CPU-06/CPU-09/CPU-10/CPU-13 (1.04-1.40x).
- Kept map/count cells all name `cache-lines`: MAP-01, MAP-02, COUNT-01, COUNT-02, COUNT-03.
- The kept map/count moves carry no licensing theorem: MAP-01 is the only `proved`-adjacent one (`pcw_spec`), the rest are `none`.
- Every whole-model GPU row is red against CUDA and unattributed: GPU-04, GPU-05, GPU-06, GPU-07, GPU-08, GPU-13, GPU-15.
- The kept GPU moves are narrow and primitive-level: GPU-01 (`mma`) and GPU-02 (`shared-bytes`) against the red whole-model set.
- The gap analysis refutes both cheap explanations of the GPU loss: GPU-11 (`launches`) and GPU-12 (`global-bytes`) each come back not-binding.
- The refuted map levers carry no numeric receipt, only the epic's list: MAP-09, MAP-10, MAP-11, MAP-12, MAP-13, COUNT-04.
