# Apeiron Word Refinement Proofs

Aeneas extraction and refinement proofs for the Apeiron `Cell<i64>` kernels. Two Lake packages,
so the machine-word extraction and the corpus link can be built and trusted separately:

| Package | Directory | Role |
| --- | --- | --- |
| `apeironWordProof` | `proof/` | Extract the kernels and define their `ZMod (2^64)` denotation |
| `apeironWordBridge` | `proof/corpus/` | Compile the canonical corpus and prove the refinement link against `AnyRing` |

Neither is imported by the `apeiron` crate.

This file is the proof authority for the extraction and bridge under `proof/`. The canonical corpus
is in-tree at `proof/canonical/`. The table claim's scope and trust boundary are stated below.

## Purpose

Apeiron is the O(1)-primitive basis at fixed N with bounded callbacks and nonconstant key length,
evolved from hashtrinity; `fold/hashtrinity` is the naive predecessor. The basis is
`R[x]/(x^2 - sigma)`, `Cell<R>` with `Sigma` as a value in every executing signature, `Coord`
addressing correct per face, and the executing growable `Table`: a flat certified-coordinate
resident area plus grouped spill regions, keyed by `(Sigma, K)` with `Stored`/`Regen` carriers. The
historical fixed-shard `Table<K, V, H, N>` (one home shard, `ShardFull` refusal, `N = 0` refusal)
and its bounded-admission proofs are revision-bound historical evidence, not proofs of the executing
layout. Every executing face refines the canonical object; anything not rooted in it is not
accepted. The canonical object is
`Apeiron.Table.{HMap,get,insertWith,build}` and
`Apeiron.Trichotomy.AnyRing.{RingCell,ringMul,ringNormForm}` with the extracted `Cell<i64>` word
bodies (`word_mul_denote`, `word_norm_denote`).

The O(1) qualifier is the parameter boundary. Fixed N, bounded callbacks and nonconstant key length
bound the table; reading a whole source remains at least linear in its bytes at fixed N, so
constant-time table operations at fixed N do not imply constant-time whole-source checking or
constant-size proof terms.

## Stage 1: extraction (`proof/`, alias `apeironWordProof`)

- `extract/lib.rs` includes the real scalar, cell, exchange, carrier, coordinate and growable-table
  modules by `#[path]`. Its monomorphic wrappers only fix concrete types and call the real methods.
  `regen.sh` selects the roots with its `--start-from` entries: cell, carrier and exchange kernels;
  codec and carrier operations; public get/build operations; prepared-shard operations;
  straight-line get/insert applies; the schedule check; coordinate, relocation, pending-and-commit
  and prepared-publication operations; and the capacity-bound check. Their call closure includes the real `spill_read`, `spill_locate`, constructor, search, insertion,
  relocation, resource-publication and ordered-build bodies.
- `ApeironWord.lean` is generated by Aeneas; `regen.sh --check` fails on drift.
- `Denotation.lean` proves the wrapping word operations are the ring operations under
  `denote : I64 → ZMod (2^64)` reading the **bit pattern** (unsigned):
  `denote_wrapping_add/sub/mul` (plus `denote_zero/one`).

```sh
proof/regen.sh                 # extract, audit, build
proof/regen.sh --check         # fail if ApeironWord.lean is stale, then build
AENEAS_HOME=/path/to/aeneas proof/regen.sh
```

### The checked-claim kernel

`accept_derived_impulse` selects its branch with an explicit `if` on the derived `Cell` equality.
Charon therefore translates the equality and the branch rather than the external
`core.bool.Bool.then` combinator, so the kernel adds no `axiom` to the generated file (the four
boundary axioms listed under Evidence cones belong to the `f32` attention carrier). The generated equality `cell.Cell.Insts.CoreCmpPartialEqCell.eq` compares the two word
slots in turn, so the acceptance obligation is decided by source-word equality; the corpus theorems
below prove the exact acceptance/rejection behaviour without reading `ZMod (2^64)` equality back as
word equality.

## Stage 2: refinement (`proof/corpus/`, alias `apeironWordBridge`)

`WordRefinement.lean` proves, over `Apeiron.Trichotomy.AnyRing` instantiated at `ZMod (2^64)`:

- `word_mul_denote`: extracted `Cell::mul` = `ringMul`;
- `word_norm_denote`: extracted `Cell::norm_form` = `ringNormForm`;
- `word_norm_mul`: transfer of `ringNormForm_mul`;
- `word_mul_conj`: transfer of `ringMul_conj`.

The dial is carried as `denoteSigma := denote ∘ sigmaI64`; no numeric case analysis of `-1/0/1` is
needed for the algebra. All four are total `ok` equalities, with no `sorry` and no reduced domain.

### Point density and flux refinement

`word_point_density` and `word_point_flux` are the extracted `i64` specialisations of the real
`src/carrier.rs` generic kernels, which build `(amplitude, 0)`, multiply by the direction and take
the norm form (`point_density`), then multiply by the forward phase difference
(`point_flux`). `WordRefinement.lean` proves:

- `word_norm_of_mul_denote`: the shared step, composing the extracted `word_mul` and `word_norm`
  refinements to give the canonical `ringNormForm` of the canonical `ringMul` product;
- `word_point_density_denote`: extracted `word_point_density` = `Apeiron.Physics.pointDensity` at
  the symbolic dial `denoteSigma s`;
- `word_point_flux_denote`: extracted `word_point_flux` = `Apeiron.Physics.pointFlux` at
  `denoteSigma s`, composing the density refinement with the wrapping `sub`/`mul` denotations;
- `word_point_density_eq`: transfer of the canonical `pointDensity_eq` factorisation into the
  amplitude's and direction's norm forms;
- `word_point_density_ringOne` / `word_point_density_ringOne_independent` and
  `word_point_flux_ringOne` / `word_point_flux_ringOne_independent`: the unit-direction
  specialisations, where the dial drops out, matching the canonical `pointDensity_ringOne` /
  `pointFlux_ringOne` and their independence theorems;
- `word_point_density_total`: the density kernel is total.

All are total `ok` equalities for every full-width input and every dial value, with no `sorry`.
The denotation theorems compose `word_mul_denote` and `word_norm_denote`; they do not restate the
polynomial.

### Scalar carrier step and exact-half flux

`word_conservative_density_step` and `word_diffusive_flux_half` are the extracted `i64`
specialisations of the real `src/carrier.rs` kernels. Both are **partial**: an intermediate that
does not fit `i64`, or an odd face difference, is refused as `ok none`. `WordRefinement.lean`
proves, over `ZMod (2 ^ 64)`:

- `word_conservative_density_step_denote`: a successful extracted step denotes
  `Apeiron.Physics.scalarCarrierStep` at the denotation of its four `i64` arguments;
- `word_conservative_density_step_eq_some_iff`: the step succeeds exactly when all three generated
  checked intermediates (`outgoing - incoming`, `density - net`, `after + source`) are `some` — the
  exact generated no-overflow precondition;
- `word_conservative_density_step_success`: under those three preconditions the step succeeds and
  denotes the canonical `scalarCarrierStep`;
- `word_diffusive_flux_half_denote`: a successful extracted half-flux satisfies the canonical
  `Apeiron.Physics.exactHalfFlux` witness `2 * f = left - right`;
- `word_diffusive_flux_half_success`: under representability (`right - left ∈ [i64::MIN, i64::MAX]`)
  and evenness of the face difference, the kernel succeeds and the result is that witness;
- `word_diffusive_flux_half_odd_refusal`, `word_diffusive_flux_half_unrepresentable_refusal` and
  `word_conservative_density_step_overflow_refusal`: concrete inputs on which the kernels return
  `ok none`, so partiality is real and no theorem claims totality.

The denotation proofs read the generated `I64.checked_sub`/`checked_add`/`checked_rem`/`checked_div`
specs and carry each result through `denote`; they do not restate the arithmetic. The `?` operator
is not used in these two kernels because it desugars through `Try::branch`, which Aeneas
has no model for; the source uses explicit `match` with early `return None` instead. No claim is
made that every integer state is iterable or that the updated value remains a norm-form square.

### The three-cell diffusive line

`word_diffusive_line3_step` is the extracted `i64` specialisation of the real
`src/carrier.rs::diffusive_line3_step`: a closed three-cell line with `nu = 1/2`. The two interior
faces are read once each from `word_diffusive_flux_half`, the two endpoint faces are fixed at zero,
and the three cells are updated by `word_conservative_density_step`. Every local is computed before
the result is constructed, so a late refusal returns `ok none` with no partially updated line.
`carrier::DensityLine3` is a plain `Copy`/`Eq` triple; the extracted `carrier.DensityLine3` is the
generated struct. `WordRefinement.lean` proves:

- `word_diffusive_flux_half_cases` / `word_conservative_density_step_cases`: each partial kernel
  either succeeds with a word or returns `ok none`, the case split the composition needs;
- `word_diffusive_line3_step_eq_some_iff`: the step returns `some next` exactly when both faces
  exist, all three checked cell updates succeed, and `next` is their componentwise result;
- `word_diffusive_line3_step_denote_of` / `word_diffusive_line3_step_denote`: on success the two
  interior faces are `Apeiron.Physics.exactHalfFlux` witnesses and each updated component is the
  canonical `Apeiron.Physics.scalarCarrierStep` at the shared face and closed end;
- `word_diffusive_line3_step_total_mass`: the denoted total changes only by the denoted sources,
  proved by instantiating the existing `word_conservative_total_mass`, not a second telescoping;
- `word_diffusive_line3_step_total_mass_zero_source`: the zero-source conservation corollary;
- `word_diffusive_line3_step_zero_success`: the all-zero old/source line returns the all-zero line as
  `some`, so the success branch is inhabited and the partial kernel is not vacuously total;
- `word_diffusive_line3_step_odd_refusal`: the odd interior difference `1 - 0` refuses the whole
  line, so the step is not total;
- `word_diffusive_line3_step_unrepresentable_refusal`: with all three cells at `i64::MAX`, the
  interior differences are even (faces `0`), the left cell succeeds, and the centre cell's
  `after_net + source` (`i64::MAX + 1`) is unrepresentable, so the whole line returns `ok none` — a
  line-level unrepresentable refusal distinct from the odd-face one.

The composition is a `ZMod (2 ^ 64)` statement over the three-cell line, not a physical mass law;
it inherits the partiality and the no-partial-result shape of the two scalar kernels.

The canonical corpus carries the whole-line ring statement this refines. It adds
`Apeiron.Physics.diffusiveUpdate_half_three_anyRing`: at the explicit `DoublesTo ν 1` witness and a
closed right ghost face, the two shared faces are `exactHalfFlux` witnesses, each cell averages with
its neighbor and the three-cell total is conserved — the ring analogue of the real
`CarrierDissipation.diffusiveUpdate_half_three`. At `ZMod (2 ^ 64)` there is no `ν` with
`2 * ν = 1`: reducing `2 * ν = 1` modulo `2` gives `0 = 1`. So `DoublesTo ν 1` is unsatisfiable and
the ring theorem is vacuous at the bridge's ring. The extracted-word refinement above therefore
carries the face value
itself rather than a scalar half: the two interior faces are `exactHalfFlux` witnesses
(`2 * f = left - right`) and each component is `scalarCarrierStep`. That is the non-vacuous
extracted counterpart, not a restatement of the corpus theorem.

No energy claim crosses into the word ring. The corpus proves the exact real identity
`dirichletEnergy_halfStep_three` (`E' = (1/4) * E` at `ν = 1/2` with the right ghost face closed)
and its strict form `dirichletEnergy_halfStep_three_lt` for positive energy; the factor `1/4` needs
the order of `ℝ`, so `diffusiveUpdate_half_three_anyRing` and this bridge make no such claim.

### Exchange refinement

`Apeiron.Physics.CarrierBodyWorkAnyRing` (corpus) carries the equal-mass exchange to an arbitrary
commutative ring, so `Z/2^64` is an instance rather than an analogy. It defines `ringExchangeImpulse`,
`ringCarrierMomentumAfter`, `ringBodyMomentumAfter` and `ringNormFormLedger` on
`Apeiron.Trichotomy.AnyRing.RingCell R`, and proves:

- `ringCarrierMomentumAfter_eq` / `ringBodyMomentumAfter_eq`: the exchange swaps the two momenta;
- `ringExchangeImpulse_antisymm`: the impulse is equal and opposite;
- `ringTotalMomentum_conserved`: the total basis momentum is unchanged;
- `ringNormFormLedger_conserved`: the `ringNormForm` ledger is unchanged at every dial value.

This is the norm-form ledger, not kinetic energy; `ringNormForm` is indefinite in a general ring and
no nonnegativity is claimed. The real-valued `Apeiron.Physics.CarrierBodyWork` is **not** transferred
to wrapping words by name; the ring-generic file is the specification the wrapping words refine.

`WordRefinement.lean` links the extracted `i64` kernels to it:

- `word_exchange_impulse_denote`: extracted `word_exchange_impulse` = `ringExchangeImpulse`;
- `word_elastic_exchange_denote`: extracted `word_elastic_exchange` = the canonical impulse,
  carrier and body fields;
- `word_elastic_exchange_carrier` / `word_elastic_exchange_body`: transfer of the swap;
- `word_elastic_exchange_totalMomentum`: transfer of total-momentum conservation;
- `word_elastic_exchange_normFormLedger`: transfer of ledger conservation at every symbolic
  `denoteSigma s`;
- `word_exchange_impulse_antisymm`: transfer of impulse antisymmetry;
- `word_accept_derived_impulse_spec`: the checked-claim kernel returns `some` exactly when the
  claim equals the derived word impulse (a single iff);
- `word_accept_derived_impulse_rejects` / `word_accept_derived_impulse_rejects_of_ne`: any claim
  unequal to the derived word impulse is rejected with `ok none`;
- `word_accept_derived_impulse_accepts` / `word_accept_derived_impulse_accepts_derived`: the exact
  derived word impulse is accepted and returns the elastic exchange;
- `word_accept_derived_impulse_denote` / `word_accept_derived_impulse_denote_canonical`: the
  accepted exchange denotes exactly what `word_elastic_exchange` denotes, and through the existing
  `word_elastic_exchange_denote` the canonical ring exchange impulse and momentum updates.

All are total `ok` equalities for every full-width input and every dial value, with no `sorry`.
The acceptance proofs select the branch by source-word equality of the two `I64` slots
(`word_cell_eq_eq`) and carry the result over with `word_elastic_exchange_denote`; they never infer
word equality from `ZMod (2^64)` equality.

### Executing growable representation and open obligations

The growable flat/spill representation executes. Its extraction is checked fresh by
`regen.sh --check`, and the current conditional bridge builds under the closed axiom cone; universal
read refinement and construction of the remaining premises are open. The fixed-shard word
refinement above is revision-bound historical evidence. Open proof obligations:

- **Flat resident plus spill representation.** The storage contract specifies a shard-major `256 × L`
  flat area (`live` is the sole occupancy authority) beside independently load-sized grouped spill
  regions (tags are the sole occupancy authority). Checked density and budget select flat residency;
  exclusion spills rather than refusing. Extent growth reclassifies newly admitted spill keys by a
  transactional rebuild. Composite `DirectCover`, unique representation and
  `Site = FlatFound | FlatVacant | SpillFound | SpillVacant | NeedSpillGrowth` are open.
- **Key representation.** `Stored<K>` retains `K`; sealed `Regen<C>` retains `u64`. Both preserve
  `Sigma` separately. Regeneration requires the exact admitted-domain codec round trip and the
  verified inverse of `Addr.id`, never `Addr.place`; `direct_word = Some(w)` alone cannot justify
  dropping a key. These are open premises, not extracted facts.

- **Extraction freshness.** The real `spread`/`finish` identity-word bodies, the `Stored`/`Regen`
  carriers, probe loops and prepared/apply roots are on the extracted path. On the recorded identity,
  `proof/regen.sh --check` built 1708 jobs and exited 0; a generated shard-count mutation exited 1,
  and restore exited 0. Freshness must be re-established after any extraction-source change.
- **Identity-injectivity integration.** Canonical odd-multiply injectivity at
  `Apeiron/Table/WordIdentity.lean` (registered in `Audit.lean`) and the Rust refinement at
  `proof/corpus/TableRefinement/CoordIdentity.lean` (`coord_spread_id_injective`) are present and
  registered for audit; binding that chain to the selected source and the growable
  search/relocation refinements remains open, and this chain must not enter `Iota.*`.
- **Unextracted threading boundary.** `std::thread::scope` sits behind an unextracted orchestration
  boundary; the extracted roots are the sequential partition, worker and assembly bodies. The
  schedule obligation composes the implementation-specific per-key subsequence equation with
  `Apeiron.Table.build_eq_of_key_streams_eq` and covers sequential worker semantics and schedule
  preservation only. Rust thread memory semantics, exclusive-borrow realization, spawn/join failure,
  panic propagation, liveness, allocator behaviour and rustc/LLVM codegen remain open.
- **Resource/refusal contract.** Checked reservation/allocation failure is selected. Locate precedes
  a complete checked plan and reservation of all fallible storage; initialization/relocation runs
  without merge, merge runs exactly once, then commit occurs. `Err` changes no committed state and
  runs no clone, merge or relocation. Allocator simulation and refusing witnesses remain open.
- **Conditional relocation/rebuild scope.** `PayloadStateEq` equates `default`, `home`, `resident`,
  `shards`, `len` and `key`; it excludes `locator`, so it is not whole-state equality or a
  canonical-map refinement. `TraversalEffectsPrepared` supplies `run_eq`, `payloadState` and
  `reservedRep` for its returned `nextState` and `nextStorage`. The bridge audits that structure and
  the conditional headlines, but the unextracted planner/resource boundary must construct it.
- **Complete bridge set.** The current `Growable.*` roots carry audited conditional headlines from the
  storage contract.
  The bounded bridge build passes 3482 jobs on the fresh artifact and `AxiomAudit.lean` accepts its
  registered declarations under `{propext, Classical.choice, Quot.sound}`. Those results prove the
  stated conditional theorems, not their open premises or universal public-read correctness.
  Stable partition and assembly must provide the exact
  per-key value-subsequence premise of canonical `Apeiron.Table.build_eq_of_key_streams_eq`; grouped
  readback and any partial reduction need their own order or merge law.
- **Iota empty-cone separation.** The constructive Iota source-refinement chain requires an empty
  axiom cone; the Rust/Aeneas bridge and the canonical corpus retain
  `{propext, Classical.choice, Quot.sound}`. The two cones share no declarations, and a `ZMod`-based
  bridge declaration is not importable into the empty-cone chain.

Open, each needing its own review: flat geometry and constructor joint witnesses; composite

### Corpus / toolchain compatibility

The canonical corpus is in-tree at `proof/canonical/`, a Lake package that `proof/corpus/lakefile.lean`
requires by path (`../canonical`); the bridge reads no other corpus checkout. The corpus and the
bridge both pin Lean `4.31.0` and Mathlib `v4.31.0` (manifest revision
`fabf563a7c95a166b8d7b6efca11c8b4dc9d911f`), the backend the pinned Aeneas extraction uses. The
corpus is a copy of the `proof/` tree of the author's earlier corpus repository at revision
`880aa57e47e782ed7a9d9ee1974cfc87360b446b`; that repository is not part of this one, so the
revision is recorded as provenance and cannot be resolved here.

Comments in the Lean and Rust sources cite sibling paths (`../sanguine-ref/…`, `../song/…`,
`../fold/…`). They name the author's predecessor repositories as provenance for a statement or a
port. Those repositories are not part of this one and nothing here reads them: no build step, gate
or theorem depends on a sibling path. The code that was carried over is the author's own, under this
repository's licence.

Reproduce with a built `proof/` and `cd proof/corpus && lake build`. A cold build compiles Mathlib
and the corpus and exceeds an hour on a single thread; CI builds it and uploads the log.

## Evidence cones

Two evidence cones are kept distinct.

- The constructive Iota source-refinement chain requires an **empty** axiom cone. Every registered
  declaration, instance, witness and headline audits with an empty axiom set under
  `proof/corpus/Iota/Audit/Empty.lean` and `tools/iota/zero_axioms.py`; `propext`,
  `Classical.choice`, `Quot.sound`, `noncomputable` and quotient-based representations such as
  `Finset` and `ZMod` are rejected there. The source word ring is the constructive, locally supplied
  `Iota.Refinement.WordRing` over `Iota.Word`.
- The Rust/Aeneas bridge and the canonical corpus retain the closed cone
  `{propext, Classical.choice, Quot.sound}`. The extracted `Cell<i64>` word theorems and the table
  headlines depend only on those standard axioms.
- The generated `ApeironWord.lean` also declares four boundary `axiom`s for the `f32` attention
  carrier (`core.f32.F32.is_finite`, `attn.alloc_f32_storage`, `mixer.f32_carrier.q32_to_f32`,
  `attn.KvState.attn_head_f32`): operations Charon does not translate and the pinned Aeneas model
  does not define. `proof/boundary-axioms.txt` lists them and `proof/audit-extraction.py` accepts
  exactly those names. A theorem about their users is proved relative to what the four assert, not
  for the hardware `f32` path. `AxiomAudit.lean` throws on any audited headline outside the standard
  cone, so none of them uses these four.

`install-patches.sh` locates a source checkout, verifies its `HEAD` commit, git tree and base file
digests against `PINS`, then checks or applies both patches. The Charon source defaults to
`$AENEAS_SRC/charon`. Aeneas source resolution is `--aeneas-src`, then `APEIRON_AENEAS_SRC`, then


does not apply. Install mode applies the patches to the checkout and skips a patch already applied;
the two modes were exercised against a fresh checkout of both pinned revisions, and the applied
working-tree diff is byte-identical to the patch files.

### Route from a clean checkout to a built `proof/`

`proof/lakefile.lean:19` is `require aeneas from "../target/aeneas-model/lean"`, and the committed

| step | command | what performs it |
| --- | --- | --- |
| 1. install the pinned tools | `proof/bootstrap.sh` | fetches the sha256-pinned Aeneas archive, materialises the pinned Aeneas/Charon revisions, applies `patches/*`, builds when the pinned products are absent, strips each binary (`strip -R .note.gnu.build-id`), installs `target/aeneas`, runs `model-patches.sh` and asserts `PINS:AENEAS_TRANSLATOR_SHA256` plus `CHARON_SHA256` and `CHARON_DRIVER_SHA256`; `regen.sh` defaults `AENEAS_HOME` to `target/aeneas` and symlinks `target/aeneas` to an installation named elsewhere |
| 2. materialise the patched Lean model | `proof/model-patches.sh` | copies `${AENEAS_HOME:-$REPO_DIR/target/aeneas}/backends/lean` to `target/aeneas-model/lean` and applies `patches/aeneas-lean-model.patch` with `patch -p1 --forward` (step 1 runs it) |
| 3. extract, audit and build `proof/` | `proof/regen.sh`, or `proof/regen.sh --check` | extraction reads `LEAN_BACKEND="$AENEAS_HOME/backends/lean"`, the unpatched installed backend; its `lake build` resolves the `aeneas` path dependency from step 2 |

Step 2 precedes step 3 because `lake` resolves `../target/aeneas-model/lean` before any module is
built, and `regen.sh` does not create it. `model-patches.sh` parses no arguments: it has no `--help`
and no `--check`, and it always removes and rebuilds the destination. It symlinks
`proof/.lake/packages` to `target/aeneas-model/lean/.lake/packages`; `ln -sfn` succeeds on an absent
target, so the symlink is created before step 3 populates that directory.

The model exists because the pinned release does not model the externals the growable table reaches
and carries no `Vec` capacity: `proof/lakefile.lean:14-18` lists them (`Vec` capacity,

unpatched backend and the model supplies the missing Lean definitions, so step 2 changes the built
package, not the generated file. `proof/strip-modeled-axioms.py`, run by `regen.sh` after generation,
removes the axiom stubs the model now supplies.
