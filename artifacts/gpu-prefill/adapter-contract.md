# Apeiron to Fold prefill adapter contract

Grade: source-bound **anchor** plus Python **model** witnesses. No Rust extraction/refinement, emitted-SPIR-V execution, GPU parity, or new timing is claimed.

## Existing production surfaces

Apeiron `src/format/quant.rs::q8_0_codes` reads a Q8_0 block as an `f16` scale plus 32 signed `i8` codes. Its block offset multiplication is checked, but `o + Q8_0_BLOCK_BYTES` is ordinary `usize` addition before `need`; multiplication fitting does not prove that addition safe. Until the source is repaired or a reachable caller precondition is proved, the adapter domain includes `o <= usize::MAX - 34`; outside it the current API can panic rather than return `QuantError`. Do not model that edge as a total refusal.

`src/engine/chart/mod.rs::quant_act` builds `QuantAct` with signed codes in `[-127,127]`, one Q32.32 power-of-two scale per 32 lanes, including ragged final blocks. It returns `None` if code/dequant invariants fail. Empty input quantizes to empty, but `gemm_q8_0` rejects empty activation columns and `prefill_state` rejects an empty prompt. `src/engine/kern/gemm.rs::exact_dot` consumes signed Q8_0 weights and `QuantAct`, accumulates checked `i128`, then applies one `round_shift_32` and an `i64` range check. It is a candidate small real-source extraction target; the current extraction/refinement does not include this body.

Fold's `gemv_dp4a_batch_rt_module` consumes the six bindings `W, XQ, OUT, DM, XS, SX`. Its Q8 weight words contain unsigned codes and are k-packed at `W[(k/4)*M+row]`; activation words are signed lanes with `K/4` words per token; output is `OUT[token*M+row]`; `DM[block*M+row]` stores f16 `(d,lo)`; `XS` and `SX` are token-major per-block values. `GemvSpec::legalize` and the emitter require `K % 32 == 0`. The batched emitter has no batch guard: the caller pads token count to a multiple of `bt`; padded activations must be zero and padded output rows discarded. Its live output row stores are guarded.

Fold's current serving pack path does not provide an Apeiron Q8 adapter: `row_chart_of` has no Q8 row kernel and returns an empty CPU chart for Q8, leaving the f32 mirror. The GPU six-binding path is a usable existing target, not proof of a ready-made conversion or of whole-stack Q8 serving. `GpuPrefillStack` currently admits its documented uniform dense fused-QKV domain; it does not establish batched DeltaNet recurrence. Hybrid state needs a separate contract against Fold's existing recurrence primitives.

## Candidate per-32 mapping and rejection domain

For each Apeiron Q8_0 block, map a signed weight code `q` to Fold's unsigned code `u=q+128`. For exact real arithmetic, select `d_fold=d_q8` and `lo_fold=-128*d_q8`, since `d_fold*sum(u*x)+lo_fold*sum(x)=d_q8*sum(q*x)`. This is a model identity only. Both values must be finite and exactly representable in Fold's f16 DM fields; otherwise refuse this adapter. Repack words from Apeiron row-major blocks into Fold's k-packed `W`, without changing lane order. No production converter currently implements or validates this mapping.

Apeiron activation lanes pack directly by signed code identity into XQ; the existing power-of-two block scale converts to SX only when exact and finite in f32. Compute XS from reconstructed code-times-scale lanes, in the registered float order. Do not route those lanes back through Fold quantize_at: that operation requantizes and can change XQ/SX. Original unquantized input sums also change the affine correction. The source-to-f32 representation and sum order require an actual-body link. Reject non-multiple-of-32 K, zero dimensions, checked-size overflow, invalid/unrepresentable scale/offset and non-exact conversions. The existing Q8_0 addition-overflow edge remains a panic boundary unless the add-safe premise is established.

Preserve the emitted float epilogue's operation association bit-for-bit, including the existing order of multiply/add operations. Apeiron `exact_dot` returns fixed-point `i64` after integer/i128 accumulation and one rounding; Fold writes f32 through its affine chart epilogue. The mapping equation does not prove these observations equal. Do not replace Fold's float epilogue with fixed point or claim exact end-to-end equality from matching argmax.

## State, padding, and resource ownership

Bind state with `(model source digest, explicit session generation, carried-prefix length, validated shape)`. A continuation is admissible only for the same model digest and session generation, a prefix equal to the GPU KV prefix, and unchanged capacity/layout. Allocate a fresh monotonically increasing generation for each session/reset; raw pointers are not identities. On identity mismatch, non-prefix input, capacity mismatch, or reset, clear/reinitialize KV and every recurrent buffer before executing. Never reuse another session's buffers. Constructor-derived capacities and all `usize`/`u32` products must be checked before allocation or dispatch.

Successful domain witnesses are: one finite representable Q8 block; a batch padded with zero activation rows and only live results observed; a same-session next chunk preserving KV prefix; and reset creating a fresh generation with cleared KV/recurrent state. Refusal witnesses are empty prefill, K not divisible by 32, unrepresentable f16 affine offset, unsupported chart/shape, checked allocation overflow, stale or foreign session generation, and changed prefix. These are adapter-contract witnesses, not current Rust/GPU tests.

The executable gate binds these statements to source digests and symbols and exercises integer/layout/state model witnesses plus attributable mutations. It cannot show that the future adapter is on the production path. The next small source-linked target is `exact_dot`: extract the actual Rust body with the real `f16_split`, checked accumulation and `round_shift_32`, then prove the bounded Q8_0/QuantAct row result and reject a changed multiply/rounding body. Separate links remain necessary for the packer, emitted float epilogue, resident constructor/run, KV continuation/reset, and hybrid recurrence. GPU device execution, driver/compiler lowering, resource lifecycle and measured whole-prefill performance remain open.
