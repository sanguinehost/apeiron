# nq: int8 KV — a 2.27× attention kernel behind a quality refusal

Criterion: **T1** (decode) mechanism, **C2** (quality) refusal, **C1** (context state) capacity row.
The int8 KV carrier stores one `i8` code per component with one f32 scale per row and runs the
sign/int8 dot on the decode path. On the box it cuts `attn.core` from 9.679 to **4.271 ms/token**
(2.27×) and the decode token from 23.11 to **18.46 ms** (41.7 → **55.0 tok/s**). It also moves PPL
from **67.257790 to 100.115240** (+48.9%) on the same model, pack and token stream. The carrier is
**refused as a product route at per-row scale**: the instruction win is real, the quantiser is not.

Grade: `measured` for the walls, rates, splits and PPL; `tested` for the i8 group/tile equality
tests (8/8); `model` for the ceilings and the bytes-per-position arithmetic.

## Quality

| carrier | PPL | mean NLL | Δ vs F32 |
|---|---:|---:|---:|
| F32 | 67.257790 | 4.208533 | — |
| F16 | 71.612941 | 4.271276 | +6.5% |
| **i8** | **100.115240** | **4.606322** | **+48.9%** |

2,044 scored tokens, 4 windows of ≤512, Q8Act kernel. The i8 write quantises each K/V row by one
scale, so a row with one large component loses most of its resolution; attention scores and the
value mix both see that step. The measured mechanism is the int8 dot; the measured defect is the
per-row scale. Refused under the product line's ≤1.5× Q4_K_M PPL minimum as it stands.

## i8 prefill and the tile-pack vectorisation

The i8 prefill arm reads the same 64-position tile as the F32 arm. Its first version packed each
`i8` code to binary32 scalar by scalar; the tile's vector body then ran unchanged.

| i8 prefill | before | after | F32 arm |
|---|---:|---:|---:|
| `attn.core` | 2457.999 ms | **2327.337 ms** | 1360 ms |
| prefill wall | 4.792 s (381.25 tok/s) | **4.602 s (397.01 tok/s)** | 3.903 s (468 tok/s) |
| `ffn` | 1232.497 | 1200.812 | 1243 |
| `attn.proj_in` | 562.365 | 555.080 | 559 |

The pack vectorisation loads eight `i8` lanes, sign-extends and converts them (`_mm_loadl_epi64`,
`_mm256_cvtepi8_epi32`, `_mm256_cvtepi32_ps`), transposes eight rows into the key tile, and stores
the value rows directly — the F16 arm's shape with a different load. It recovers 130 ms; the i8
tile is still **1.71×** the F32 arm, so the remaining cost is not the pack. The unmoved share is the
per-row scale multiply over scores and weights and the int8 tile's own read; that is where the next
i8 change would go, and it is not pursued while the carrier is refused on quality.

## Correctness

- `attn_core_i8_tile` and the i8 group core equal the per-column oracle over the same codes and
  scales, over the 8/16/64/128-wide geometries, 1/2/4 query heads and the 1,024-word stride
  (`the_i8_tile_group_read_agrees_with_the_per_column_read`, `i8_group_read_*`; 8 passed).
- The vectorised pack is bit-identical to the scalar pack: the tile equality test runs the same
  codes through both.
- The first decoded token is 3845 on i8 (and on F16); F32 is 315. The carrier changes the logits.

## Refusals

1. **"i8 KV is a T1 step."** Refused as a product claim: 55.0 against 41.7 tok/s is real (1.32×) but
   PPL is +48.9%. The kernel is a mechanism, not a route.
2. **"The int8 dot is not the win."** Refused: `attn.core` 9.679 → 4.271 ms with every other term
   unchanged; the win is in the attention read, not in the projections.
3. **"i8 prefill pays for itself."** Refused: i8 prefill is 4.602 s against F32's 3.903 s (1.18×
   slower); `attn.core` is 1.71× the F32 arm even after vectorising the pack.
4. **"The carrier names the laptop."** Refused: box only.
5. **"The maintainer gate ran."** Refused: the pinned Aeneas/Charon/Lean toolchain is not
   bootstrapped and the committed extraction is stale.

## What this does not cover

Per-32-block scales (the named quality fix), 200k/1M context, the 7B, the laptop's wall, the GPU
path, code generation for rustc/LLVM, and the `unsafe` container. The i8 dot is `tested` equal to
its per-column oracle; nothing here is `proved`.
