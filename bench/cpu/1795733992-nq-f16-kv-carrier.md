# nq: binary16 KV carrier — half the plane, no wall change

Criterion: **C1** (context state) and **T1** (decode), carrier row. The key/value cache gains a
binary16 carrier: one half word per component, 114,688 B/position against the F32 carrier's
229,376, which moves the decode bandwidth ceiling from 157.8 to **235.0 tok/s**. On the box the wall
does **not** move: decode is 40.1–41.2 tok/s on F32 against 41.2/40.8/39.9 on F16, and prefill is
466.3/465.8/466.3 against 455.2/463.6/438.2 tok/s. The carrier is a capacity row for C1, not a T1
step on this host; the first decoded token changes (315 → 3845) because the stored rows round.

Grade: `measured` for the walls, rates, split and binary hashes; `tested` for the conversion,
core-equality and append tests; `model` for the ceilings and the bytes-per-position arithmetic.
Nothing is `proved`; the maintainer gate is blocked (below).

`attn.core` is unchanged (9.789 against F32's 9.679) and `--target attn.core` exits 0. Halving the
plane therefore does not halve the read: the F16 group core repacks each 8-position tile into f32
stack buffers before the committed tile body, so every KV word is written and re-read once per
token on the tile's behalf, and that traffic stands where the halved plane saves. This is a
`model` of the neutral wall, not a measurement; the measured fact is that the wall does not move.

## Correctness

- `f16_to_f32` equals `vcvtph2ps` on all 65,536 finite half patterns; `f32_to_f16_bits` equals
  `vcvtps2ph` (round-to-nearest-even) on 200,000 random binary32 patterns plus the signed-zero,
  subnormal, largest-finite and overflow-tie boundaries, and refuses a value whose rounding lands at
  infinity.
- `attn_core_f16_group` and `attn_core_f16_tile` equal the committed F32 group and tile cores over
  the same plane materialised in binary32, bit for bit, over the 16/64/128-wide geometries, partial
  tails and the real 1,024-word stride.
- `append` stores the rounded half, refuses a Q32.32 word above the largest finite half
  (70,000 → `Overflow`), and reads a subnormal half back exactly.

## Refusals

1. **"F16 halves the decode token."** Refused: 3.153 against 3.143 s, 0.997×; `attn.core` is
   unchanged. The bandwidth ceiling moves; the wall does not.
2. **"Decode is bandwidth-bound on this box."** Refused: F32 decode at 41.7 tok/s is 3.8× under its
   own 157.8 tok/s ceiling, and halving the bytes leaves the wall where it was.
3. **"The carrier is quality-neutral."** Refused: the first decoded token changes (315 → 3845); the
   KV rounding moves the logits. PPL at 200k is C2 and is not measured here.
4. **"This names the laptop."** Refused: box only; the i5-10210U has not run this carrier.
5. **"The maintainer gate ran."** Refused: the pinned Aeneas/Charon/Lean toolchain is not
   bootstrapped on either host and the committed extraction is stale. `append` now reaches
   `f32_to_f16_bits` through the extracted call graph, so `proof/regen.sh --check` is red until the
   extraction is regenerated; the AVX2 F16 body is added to the script's opaque list with the
   materialised-plane fallback as its twin.

## What this does not cover

The laptop's wall, 200k/1M context, PPL/quality (C2), the 7B, the GPU path, code generation for
rustc/LLVM, and the `unsafe` container. The F16 carrier buys half the KV plane at the F32 wall; it
does not buy time on this host.
