# 7B T=2 pack: 1.098871 b/w measured, Q4 arm 9.298465, NQ arm refused at the first norm

Criterion: **Q1** (a full 7B pack at 1.10 b/w) and **Q2** (its PPL against Q4_K_M on the same
stream). Grade: `measured` for the pack, its rate and wall, and the Q4 arm; the NQ arm produced no
number, so **Q2 is not closed** and no ratio exists.

Result in one line: 196 sections at **1.098871 b/w**, **896,312,736 B**, fit **6.854 h** on the
i9-12950HX; Q4_K_M scores **9.298465** on 2,044 tokens; the packed arm exits 1 in under a second
with `ppl: norm: OutOfRange` because the T=2 o/down factors are unconverged and gain their outputs
by 10^4–10^6 over the dense arm.

The NQ arms print the pack summary and then refuse:

```text
pack: 196 linears, 1.098871 b/w, 896306432 factor bytes
pack factors: 896306432 stored bytes for 6525288448 weights, 1.098871 b/w
ppl: norm: OutOfRange
```

That is `StepError::Norm(NormError::OutOfRange)` from the checked `rms_norm_fixed`: the row's
sum of squares, the `mean + eps` argument, or `fixed_rsqrt` leaves the fixed domain. It fires before
any NQ linear's output can be read: the pack summary is the last line, and the run dies in under
1.5 s, while one 512-token window of this model takes about 23 s. The Q4_K_M skeleton runs the same
tokenizer and stream without the pack at 9.298465, so the skeleton, data and token ids are sound in
the dense path. The F16 skeleton fails identically, so the Q4_K `token_embd` is not the cause.

The packed path in this tree is not broken in general: a control on the same binary with the 0.6B
`skeleton-q8head.gguf` and `nq06-v3.nqp` at `--tokens 64 --ctx 64` prints
`ppl 3711.143871 on 63 tokens (1 windows of <= 64, kernel Q8Act): mean nll 8.219095, 12.6 tok/s` and
exits 0. The pack's header geometry, 196 sections against the skeleton's 196 linears, and the
`install_nq` checks pass.

### Root cause: the T=2 factors are unconverged, not a kernel fault

The failure reproduces locally on the i5-10210U with the Q4_K_M skeleton and the same pack at
`--tokens 8 --ctx 8`, exit 1 in about one second. Temporary instrumentation (since reverted) printed
the activation max at each `rms_norm_fixed` and each projection, in Q32.32 words:

| stage, layer 0 | packed arm | dense Q4_K_M arm |
|---|---:|---:|
| embedding, attn-norm input | 2.47e8 (0.0575) | 2.47e8 (0.0575) |
| `attn_q` output | 1.70e11 (39.6) | — |
| `attn_k` / `attn_v` output | 6.0e10 / 6.5e10 (14 / 15) | — |
| `attn_output` (o) | **1.21e13 (2,820)** | — |
| ffn-norm input | **1.21e13 (2,820)** | 2.11e9 (0.49) |
| `ffn_gate` / `ffn_up` output | 1.9e11 / 1.9e11 (44 / 44) | — |
| `ffn_down` output | **1.77e16 (4.1e6)** | — |
| layer 1 attn-norm input | **>1.8e16 (4.2e6)** | 1.5e10 (3.5) |

The exact reader (`--kernel exact`, no q8 activation quantization) gives the same o and down bands,
1.21e13 and 1.38e16, so the q8 reader is not the cause. A direct probe of the pack's factors with
`x = 1` gives o max 725 and down max 31,316 against dense row sums of order 0.1; the factors
themselves carry the gain, before any engine choice.

The fit's own loss names the same sections: the 0.6B T=400 fits have `admm_loss` 0.22–0.35, while
this 7B T=2 fit reports q 605.35, k 955.48, v 9,094.46, o 10,546.15, gate 45.95, up/down 58.6.
The v and o factors are two to four orders from the 0.6B band, and their outputs are the first
stage that leaves the norm's range. **T=2 is not a fit of this model**: the factors are
underconverged and ill-conditioned, so this pack is not a quality upper bound either — the packed
forward diverges before a token is scored. The next lever is a converged fit (T=200, or a GPU fit),
not a T=2 re-fit and not a kernel change.

The >1000× PPL guard never fired because no NQ number exists. No tuning was attempted.

## What this does not cover

- **T=2 against a T=400 reference.** The pack is underconverged and, with no NQ PPL, not even an
  upper bound on the converged ratio is produced.
- **The example driver, not the tuned reference pipeline.** No `--rel`, so no per-linear factor
  error; no layer control; no residual.
- **Uniform 1.10 b/w.** No layer-0 D6 allocation; every kind is at the rank its bit budget names.
- **2,044 tokens at ctx 512.** The ctx-2,048 extension was conditional on a ratio ≤1.5 and was not
  reached; no 8,176-token row exists.
- **Head and embedding.** Both arms serve the skeleton's `Q6_K` `output.weight` and `Q4_K`
  `token_embd`; the pack replaces neither, so a head contribution to any future ratio is untested.
- **0-shot, the 200k context and Intent integration** are untouched.
- **Why the T=2 factors gain so hard.** The layer-0 o and down outputs are 10^4–10^6 above the dense
  arm, and the exact reader agrees with the q8 reader, so the factors are unconverged rather than
  misread. A T=2 versus T=400 control on the 0.6B at one layer would separate "too few iterations"
  from a 7B-only conditioning failure; it is not run here.
- **A converged 7B fit.** T=200 is 504 h on this CPU class (`tools/fit-budget.py` refuses it), so
  the next Q2 attempt needs a GPU fit or a higher-rate o/down allocation that keeps the gain
  bounded.
- rustc and LLVM code generation, the kernel ABI, the Vulkan driver and the GPU, and the `unsafe`
  container are outside every number above.
