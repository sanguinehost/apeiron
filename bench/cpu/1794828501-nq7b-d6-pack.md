## 3. The projection, and the stop

Per iteration the `down` fit moves ~778 G MAC (447 G data + 206 G Gram + 125 G solve/inverse). At
94.06 s that is 8.3 G MAC/s delivered. At 1.1M ppm the three big kinds (`down`, `gate`, `up`) have
the same shape and rank 3296; `q,k,v,o` have rank ~1955 and ~50 G MAC. The seven-kind iteration is
~324 s, i.e. 3.45× `down`.

| budget | wall |
|---|---:|
| `down`, T=200 | 5.2 h |
| 196 linears, T=200 | **18.0 h** |
| 196 linears, T=100 | 9.0 h |
| 196 linears, T=50 | 4.5 h (below the T=200 floor) |
| cap | 6 h |

The 5 h projection rule stops the run: 18.0 h is 3.0× the 6 h cap and 3.6× the projection limit.
The bulk, layer 0 at 3.0M, the merge and both PPL arms were not started. The measured host is
~3.3× faster per thread than the Broadwell box of `1794825968` (25.06 s against 126.61 s for the
same T=0 `down`), but the 7B shapes at rank 3296 still cost 94 s per iteration.

- A fresh GPU `ask_contract_id` with `--cancel-unavail` creates an AVX-VNNI host; `avx_vnni` is

  lower than T=0; a 1.099715 b/w, 9,333,248 B section is written.

## 7. Erratum: the 18.0 h row is per layer, not the 196-linear model

The 324 s/iteration is the **seven kinds of one layer**. `nq_fit` loops `for layer { for kind {
factorize } }`, so 28 layers multiply it by 28: **9,072 s/iteration = 2.52 h**, and the table's
"196 linears, T=200 = 18.0 h" is the per-layer figure mislabeled. The corrected table:

| budget | wall |
|---|---:|
| one layer (7 linears), T=200 | 18.0 h |
| 196 linears, T=200 | **504 h** |
| 196 linears, T=100 | 252 h |
| 196 linears, T=50 | 126 h |
| 196 linears, T=2 | **5.04 h** |
| 196 linears, T=1 | 2.52 h |

T=200 is 84× the 6 h cap, not 3×. The feasible overnight arm is **T=2, 5.04 h**, which is
underconverged against the T=400 reference and is an upper bound on the converged ratio, not a
converged quality verdict. `tools/fit-budget.py` now refuses the plan before it starts:
`--iteration-seconds 9072 --iters 200 --cap-hours 6` exits 1. This is the mistake the product-line
rule in `AGENTS.md` encodes: a per-layer figure is never a model figure. The 3.0 b/w layer-0 arm is
also not executable by `nq_fit`: the dense sign-factor cap for 3584×18944 is 1.19 b/w, and the tool
writes no residual, so layer 0 cannot be raised to 3.0 b/w by the rank alone.
