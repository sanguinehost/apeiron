# nq: per-row-scale Q8 head — 4.8× kernel, refused on stream divergence

Criterion: **T1** (decode). The head phase is 1.793 ms/token of the 6.445 ms lookup token (27.8%,
`1/(1 − s) = 1.385×`), and 94% of that phase is the `Q8_0` row kernel: 32 per-block weight scales,
one exact `i128` term per block per column. Requantizing the head to one Q32.32 scale per row and
one int8 code per weight moves the whole row dot into eight `i32` lanes and leaves one `i128`
product per (row, column).

The kernel is **4.8× faster per pass** in the tree, but the carrier is **refused**: the
requantized head changes the greedy stream at token 7, the benchmark's six-token loop does not
form, and prompt-lookup acceptance falls from 100% to 86.6%. The decoder is 18.6% slower despite
the faster head, because the number of trunk passes per token rises 1.65×.

Grades: `measured` for the kernel ratios as a synthetic comparison fixture on the box (CPU-tier
evidence; the timed target is the laptop, which did not run this); `measured` for the walls and
acceptance on the box; `model` for the phase-share ceiling. The stale `Q8_0` head's own exactness
is covered by the bit-plane equality tests, not by this refusal.

## Machine and command


## Kernel

The standalone kernel bench (`1795763918-head_bench.rs`, `rustc -O -C target-cpu=native`) runs the
same 151,936 × 1024 × 7 product both ways on the box: the `Q8_0` block-scale structure is 76.397 ms
(14.3 GMAC/s), the per-row-scale structure 17.812 ms (61.1 GMAC/s), **4.3×**.

In the tree the head phase per pass, from `--trace` and the head call count:

| arm | head ms/token | calls | ms/call | passes/token |
|---|---|---|---|---|
| `Q8_0` (`matmat_q8act`, `k = 7`) | 1.793 | 29 | 7.91 | 0.227 |
| RowQ8 (`argmax_cols`, `k = 7`) | 0.614 | 48 | 1.64 | 0.375 |

The per-call win is 4.8×; the pass count rises because acceptance falls.

## Refusal

The head weights change, so the model's logits change: the requantization error is at most half the
row scale per weight, and the greedy argmax flips where the top-two gap is below it. The measured
streams:

```text
Q8_0 : 42 15 88 11 323 279 220 16 15 339 315 279 220 16 15 …
RowQ8: 42 15 88 11 323 279 1156 315 279 220 16 24 23 15 82 …
```

The benchmark's `tg` stream is a six-token loop from token 13; the RowQ8 stream has a varied
prefix and a different period. Lookup acceptance on the RowQ8 stream is 84/97 drafts (86.6%) over
47 rounds, against 102/102 (100%) over 28 rounds on the `Q8_0` stream. Three interleaved pairs:

| arm | run 1 | run 2 | run 3 | mean |
|---|---|---|---|---|
| `Q8_0` | 6.566 | 6.470 | 6.406 | **6.481 ms/token** |
| RowQ8 | 7.673 | 7.760 | 7.632 | **7.688 ms/token** |

The lookup ids equal the greedy ids within each arm (`exact`), but the two arms are different
models. The 0.5× claim is against llama.cpp on the same stream, so the head must be bit-exact with
the `Q8_0` tensor: the requantization is not a speed change, and this carrier is not a product
route. The module and its `APEIRON_ROWQ8` dial were removed after the measurement.

## What this leaves

An exact head win must come from the per-block epilogue, not from fewer bytes: the two-stage
bit-plane already reads 18/34 of the payload and is still compute-bound on the same one-term-per-
block-per-column structure (13.85% of the mixed run at `k = 1`, against 5.46% for the dense
`k = 7` kernel). The next exact lever is the exponent decomposition of `d_b·S_b`: both factors are
a small mantissa times a power of two, so the epilogue term is one 32-bit product plus a variable
shift instead of two `i128` multiplies.
