## 1. `no_such_ask` is a CPU-only offer, not the create payload

`search offers --raw` returns CPU-only offers (`num_gpus=0`) with `cpu_ram: 0`; they are
advertised but not rentable through the asks endpoint. Create on a fresh CPU-only id (`46021870`,
12 cores, `$0.0101/h`, immediately after it appeared in `--raw`):

```text
PUT https://console.vast.ai/api/v0/asks/46021870/
{"client_id":"me","image":"ubuntu:24.04","env":{},"price":null,"disk":40.0,...,"cancel_unavail":false,"runtype":"ssh_direc ssh_proxy"}

{"error": true, "status_code": 400,
 "msg": "error 404/3603: no_such_ask  Instance type by id 46021870 is not available."}
```

A GPU id created from the same call succeeds: `{"success": true, "new_contract": 60910700}`. The
`ask_contract_id` equals the displayed `id` on every live row; the failure is that the ask does not
exist for create. Two other observations:

- `cpu_ram>=16000` in the query returns **zero** rows even when matching offers exist; filter
  `cpu_ram` client-side.
- A **stale** GPU id (`25469153`, the prior box) returns `success: false` with a `new_contract`
  and a *stopped* instance billed at storage rate. `--cancel-unavail` prevents it.

One-line fix for the owner:

```sh
ID=$(vastai search offers --raw -n 'num_gpus=1 rentable=true cpu_arch=amd64 cpu_cores>=16 disk_space>=60 dph_total<=0.07' -o dph_total --limit 1 | python3 -c 'import sys,json;print(json.load(sys.stdin)[0]["ask_contract_id"])') && vastai create instance "$ID" --image ubuntu:24.04 --disk 60 --ssh --direct --cancel-unavail
```

## 4. The T=200 bill

The marginal iteration is `(1089.98 − 126.61)/2 = 481.7 s` on 24 vCPU of a 2.4 GHz Broadwell-class
host. `down` alone at T=200 is `126.6 + 200·481.7 = 26.5 h`; the seven-kind model is ~3.4× the
`down` MAC count, ~90 h. Even T=100 is ~13 h for `down`. The cheapest AVX-VNNI offer found
(i7-13700, 16 vCPU, `$0.09693/h`) needs the 3.4 h `fit-cost.md` quotes for T=200, `$0.33`, over the
`$0.20` cap; the remaining credit is `$0.118`. (b), (c) and (d) were not run. The limiting term is
the missing AVX-VNNI, not the iteration budget: this host delivers ~1.8 G MAC/s on the limb
projection.
