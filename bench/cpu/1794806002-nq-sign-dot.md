# `NanoQuant` sign dot: 4.95× on the narrow path

Criterion: **T1** (decode), the 1.17 b/w packed 7B. Grade: **measured** for the ratio, **tested**
for the equality. Machine: i5-10210U, 4 cores / 8 threads, 15 W, 6.6 GiB, Ubuntu 24.04,
`performance`, rustc 1.99.0-nightly. The kernel is single-threaded; the session pool reports 2 CPUs.

## What changed

`src/engine/kern/nq.rs` only. `sign_dot!` is retained as the portable source and as the only `i128`
source. A new `sign_dot_i64` dispatches to `sign_dot_avx2` behind
`is_x86_feature_detected!("avx2")`; the AVX2 body drives four `i64` lanes per `__m256i`, eight
four-lane groups per `u32` word, mask `-(bit)` and `(t ^ mask) − mask`, one vector accumulator and
one horizontal fold. The three narrow call sites (`V`, `U`, dense residual) use it; the wide `i128`
sites are unchanged. A partial trailing word runs the scalar source so padding bits are ignored
exactly as before.

Equality: `the_vector_source_equals_the_scalar_source` over lengths
`{0, 1, 31, 32, 33, 64, 127, 128, 1000}`, including a pass with the tail word's padding bits forced
to `1`; the existing `the_kernel_equals_the_sequential_staged_product` and
`the_wide_accumulator_agrees_when_the_bound_leaves_i64` stay green. Integer addition is exact under
the caller's `len·max|t| ≤ i64::MAX` bound, so the vector grouping changes no value.

## The measurement

Command (release, three interleaved runs, `rank = 1024`, `inn = 4096`, one 1024×4096 pass per run):

```sh
agent-guard run -- cargo test -j 1 --release --lib --all-features --locked \
  sign_dot_microbenchmark -- --ignored --nocapture
```

Final invocation, after the last edit (a lint-only `#[allow]`; codegen identical):

| run | scalar ns | AVX2 ns | ratio |
|---:|---:|---:|---:|
| 0 | 20,402,630 | 4,425,344 | 4.61 |
| 1 | 20,666,228 | 3,913,460 | 5.28 |
| 2 | 20,057,496 | 4,005,222 | 5.01 |
| **mean** | **20,375,451** | **4,114,675** | **4.95** |

Spread `(max−min)/mean`: scalar **3.0%**, AVX2 **12.4%**. An earlier invocation of the same command
measured scalar 13.41 / 12.97 / 13.21 ms and AVX2 2.89 / 2.69 / 2.95 ms, mean ratio 4.64, spreads
3.4% / 9.2%. Both columns moved together by ~1.45× between invocations, so the absolute
nanoseconds track the machine's clock/load state; the ratio stayed 4.6–5.0.

## Verdict

The narrow sign dot is 4.95× faster. That is a kernel ratio, not a tok/s figure: the 8B v3 pack
measured 0.09 tok/s end to end and the 1.17 b/w 7B pack is not built on this laptop. The T1 claim
still needs the end-to-end decode run; this receipt does not close T1.

## Not covered

- No end-to-end tok/s, no prefill timing.
- Only `inn = 4096`, `rank = 1024`; below one 32-bit word the vector entry does setup and then the
  scalar tail, so no speedup is claimed for `len < 32` (no production call site has such a width).
- The microbenchmark calls `sign_dot_avx2` directly and excludes the per-row cached feature check.
- The `i128` wide path is untouched and scalar.
