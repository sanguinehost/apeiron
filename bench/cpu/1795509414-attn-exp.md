## What changed

`src/engine/attn/f32_core.rs` and its test module only.

- `softmax_terms` (`f32_core.rs:675`) evaluates one of the pair
  `(alpha, w) = (exp(m_prev − m_next), exp(score − m_next))`, `m_next = max(m_prev, score)`, and
  returns the other as `1.0`. The scalar twin (`f32_core.rs:888`) and the per-row loop of the AVX2
  body (`f32_core.rs:1123`) use it. Two `exp_f32_scalar` calls per score become one, the structure
  of llama.cpp `049326a` `ggml/src/ggml-cpu/ops.cpp:8546-8564`.
- The AVX2 tile body (`f32_core.rs:1076-1118`) takes eight consecutive tile rows and one
  `exp_f32_avx2` for the eight `w` arguments, the structure of `ops.cpp:8849-8871` and
  `ggml/src/ggml-cpu/vec.cpp:536-548` (8-wide `ggml_vec_soft_max_f32`). The axis differs:
  llama.cpp's eight lanes are eight key positions of one query; these eight lanes are eight query
  rows of one key, because the score stage here is key-position-major. The `alpha` vector is
  computed only when `_mm256_movemask_ps(_mm256_cmp_ps(scores, m_prev, _CMP_GT_OQ)) != 0` (some
  lane's maximum moved); otherwise the eight `alpha` words are all `1.0`.
- The score stage is transposed to `scores[(at − s) * rows + row]` (`f32_core.rs:859`, `1042`), so
  eight rows' scores for one key are one contiguous `_mm256_loadu_ps`. The transpose is in both
  arms of the A/B and writes the same score words.
- `APEIRON_ATTN_EXP=0` selects the old row loop with two scalar exps; the default is the new path.
  The flag is parsed once per process, the shape of `APEIRON_ATTN_TILE` in `step/softmax.rs`.
- The polynomial is not llama.cpp's: `exp_f32_avx2` (`src/engine/mixer/f32_carrier.rs:334`) is this
  crate's existing vector exp, tested bit-equal to `exp_f32_scalar`. llama.cpp's is `ggml_v_expf`
  (`ggml/src/ggml-cpu/vec.h:1215-1252`).
- The tile's refusal paragraph (`f32_core.rs:705-713`) is corrected: the value pass tests every row
  up to the last position, so a non-finite value row at a position no query in the tile reaches
  still refuses the tile where those queries' single-query calls would succeed. The old sentence
  claimed the single-query calls would abort at the same query; the source does not.

The tiled kernel itself is another lane's uncommitted work in the same tree. The combined
`git diff --stat` for the two files is **543 + 264 insertions**; no recorded snapshot separates the
tiling lane's lines from this exp change, so this receipt assigns no line split.

## Why the words do not change

For finite `score = s` and running maximum `p`, `m_next = max(p, s)` makes exactly one of `p − n`
and `s − n` a subtraction of equal values, which is `+0.0` in round-to-nearest (including `±0`
operands). `exp_f32_scalar(+0.0)` returns `1.0` bit-exactly: `z = +0·log₂e = +0`,
`n = round_ties_even(+0) = +0`, `r = (+0 − +0) − +0 = +0`, `y = (1 + +0) + (+0·p) = 1`,
`n1 = n2 = 0`, so `s1 = s2 = 2⁰` and `(y·s1)·s2 = 1`. Returning `1.0` for that argument feeds the
same bit pattern to every consumer as the call it replaces.

`exp_f32_avx2` equals `exp_f32_scalar` lane for lane: `exp_and_silu_avx2_equals_scalar`
(`src/engine/mixer/f32_carrier_tests.rs:213`) sweeps `−88.0..=88.0` in steps of `0.008` and
`±0, ±90, NaN, ±inf`. The 8-lane body computes the same eight `w` words and, when a maximum moves,
the same eight `alpha` words. `_mm256_max_ps(s, p)` is the scalar `if s > p { s } else { p }` for
finite operands (MAXPS returns its second operand on equality, the same word). The no-move
broadcast `_mm256_set1_ps(1.0)` is the word `exp_f32_avx2(0)` returns. Each row's
`den.mul_add(alpha, w)` and `fmadd(acc, alpha, w·v)` run in the same key order with the same words
as the row loop; the batching interleaves eight independent rows and changes no row's sequence. A
non-finite score or value refuses before either expression is evaluated, so the identity's domain
is the finite scores and values the tile admits.

The default arm and the `APEIRON_ATTN_EXP=0` arm are therefore word-identical, and both equal
`attn_core_f32_strided` by the tests below.

## Review

Reviewed by `agy` with `gemini-4-hydrogen-high`. It refused: the `phase_split` run as a gate for a
prefill-only change; the cold turn as a dominant-term claim; the leaf ratios quoted without paired
statistics; the cross-window aggregate-vs-leaf llama factor; and the line-count split against an
unrecorded snapshot. It found no counterexample in the finite arithmetic (`±0`, `score == m_prev`,
unmoved lanes in a moved group, row-group boundaries) but flagged the false refusal sentence in the
tile doc. This revision adopts all six: the cold is reported and refused as a target, the leaf
ratios carry their paired values, the llama factor is labelled `model` and cross-window, the
`phase_split` run is context, the line split is dropped, and the doc paragraph is corrected; the
mixed-group fixture covers the moved-group-with-tied-lanes branch.

A second review of the combined tree (tile, exp and the NQ block) repeated one open point: the
tile's AVX2 body is opaque with its scalar twin in the crate, but the twin is not a `--start-from`
root, so there is no refinement theorem and `proof/regen.sh --check` has not run; the claim stays
`tested`. It also flagged that the scalar and AVX2 bodies checked rows in different orders for a
mixed `ZeroSum`/`Overflow` input. That input is unreachable: with finite scores and values the
denominator starts at 1.0, every `w` is in `(0, 1]` with at least one `w = 1`, and `alpha > 0`, so
`ZeroSum` cannot fire. The bodies are aligned row by row anyway; no test can distinguish them, and
none is claimed to.

## What this does not cover

- The tail turn total is not resolved (1.043× mean paired, 2 of 3 rounds below 1); the claim is the
  tail's `attn.core` leaf. The cold turn gain is measured but not a dominant-term claim.
- The alpha skip is data-dependent: a stream where every position sets a new maximum computes the
  alpha vector exp on every group and gains less than this fixture. The fixtures cover the
  branches, not the rate.
- `exp_f32_avx2` is `tested` equal to its scalar twin over the dense sweep, not `proved`; the AVX2
  tile body is `tested` against the scalar oracle. `f32_core` has no extraction root and no Lean
  theorem. rustc, LLVM and the kernel ABI are outside the claim.
- Only the structure is borrowed from llama.cpp, not `ggml_v_expf`'s constants; the per-lane exp
  rate is this crate's polynomial. No llama.cpp run is part of this receipt; its 11.69 ms/token and
  120.6 GFLOP/s are the tiling and parity-gap receipts' numbers, from another loaded window.
- The score dot's FMA chain and the value accumulator are the next terms inside `attn.core`; this
  change does not touch them.
- Provenance: the timed binary is
