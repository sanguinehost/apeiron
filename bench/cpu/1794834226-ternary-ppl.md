# The ternary activation collapses PPL to 7.77e7: 1.07e6× the q8act control

Status: **exploratory, opened by the agent in W2 rather than requested; the path is retired.**
The measurement is retained as a negative result, not as a product carrier.

Criterion: **Q2** (quality). Grade: **`measured`** for both PPL rows; the ratio and the
proxy comparison are arithmetic and `model`; nothing here is `proved`. This note refutes one
carrier option; it closes nothing.

## Result

Same model file, same pack, same token stream, same binary, same `opt-level=0` build; the only
difference is `--kernel`:

| arm | kernel | tokens | windows | mean nll | PPL | vs control | tok/s | wall | peak RSS |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|
| control | `q8act` | 2044 | 4 | 4.290295 | **72.988013** | 1.000 | 0.6 | 3604.8 s | 374.9 MiB |
| ternary | `ternary` | 2044 | 4 | 18.168898 | **77,741,389.943726** | **1,065,125×** | 1.4 | 1483.2 s | 375.6 MiB |

The ternary arm is **+13.878603 nats/token** over the control; `exp(13.878603) = 1,065,125`. The
0.6B model is not usable under this activation quantiser.

This is the same direction and a larger magnitude than the offline proxy
(`bench/notes/ternary-act-proxy.md`: ternary 0.5416 relative dot RMS vs q8 0.0119, **45.7×**, and
2086× SSE). The proxy measured one projection; this run measures 28 layers of composition and the
error compounds. No quantiser tuning was attempted, by design: the proxy was the screen and this
was the formal decider.

## The head, stated because it changes the comparison

Both arms in this table ran `--model Qwen3-0.6B-Base-Q4_K_M.gguf --pack nq06-v3.nqp`; the v3 pack
fits 196 linears (28 layers × 7 kinds) and carries **no output head**, so both arms read the Q4
file's `Q6_K` head. That makes the 1.065e6 ratio a valid same-binary contrast.

It does **not** make 72.988013 comparable to the 74.296766 row in
`1794822341-nq06-ppl-vs-q4.md`: that row served the pack on `skeleton-q8head.gguf` (a `Q8_0`
`output.weight`) and scored 74.296766. Against that row the ternary PPL is 1,046,363×. The
difference between 72.988013 and 74.296766 (1.8%) is codegen plus head, not a ternary result.

## Protocol

`target/ternary-o0.sh` builds into `target/ternary-o0/` with
`CARGO_PROFILE_RELEASE_OPT_LEVEL=0` (the guard's derived cap terminates a release build at this
memory), then:

```sh
target/ternary-o0/release/examples/ppl \
  --model /home/lucas/models/qwen3-0.6b-base-f16/Qwen3-0.6B-Base-Q4_K_M.gguf \
  --pack /tmp/opencode/nq06-v3.nqp \
  --tokenizer /home/lucas/models/qwen3-0.6b-base-e8/tokenizer.json \
  --data /home/lucas/models/wikitext2/wikitext-2-raw/wiki.test.raw \
  --tokens 2048 --skip 0 --ctx 512 --head-batch 16 --kernel <q8act|ternary>
```

Run under `~/Workspace/tools/agent-guard run --timeout 12600 -- bash target/ternary-o0.sh`;
HEAD `735a7b06`; Intel Core i5-10210U (4C/8T), 6.6 GiB, Linux 7.0.0-42-generic. The integer
projection path is identical at both opt levels; only codegen differs, and both arms share it, so
the ratio is unaffected.

## What this does not cover

- One 0.6B checkpoint, one pack (v3, 0.977441 b/w), 2,044 tokens at ctx 512. No 8,176-token arm,
  no ctx 2,048, no 7B.
- The ternary mapping is the shipped one: one trit per term, one scale per 64 terms. A different
  scale rule or a residual is untested and is not implied by this result.
- A PPL of 7.77e7 is consistent with the measured proxy, but this run alone does not exclude a bug
  in the trit packing; the safe twin `ternary_block` and the reader tests pass, and the proxy used
  the same mapping, so the quality conclusion is the working one.
- The 63 tok/s cell measurement is unaffected: it is an instruction-side ceiling. This result says
  that ceiling is not reachable by a quality path, not that the cell is slow.
- No end-to-end decode claim: the q8act control ran at 0.6 tok/s and ternary at 1.4 tok/s only
  because of `opt-level=0`; these are not rate measurements.
