the two probes; `model` for the rank and size arithmetic; the pack itself does not exist, so Q1 is

carry the changes in §4. Calibration artifacts are local at
`/home/lucas/models/vast/q7b-results/diag-c6x29/`.

## 2. Calibration: 112 diagonals over 28 layers

Base: `nq_calib_base` on `wiki.train.raw` with the checkpoint's tokenizer, 40 chunks of 512
tokens, 20,480 tokens, `calib.c40.kld` 3,094,149,940 B. The Grams: chunks 0–5 plus chunks 11–39
(29), so 35 chunks = 17,920 tokens per layer and chunks 6–10 held out. Command:

```
APEIRON_CALIB_MODEL=/workspace/models/Qwen2.5-7B-Instruct-f16.gguf \
APEIRON_CALIB_BASE=/workspace/models/calib.c40.kld \
APEIRON_CALIB_CACHE=/workspace/models/q7b-cache \
APEIRON_CALIB_CHUNKS=6 APEIRON_CALIB_EXTRA=29 APEIRON_CALIB_CHECK_LAYER=27 \
APEIRON_THREADS=20 \
  cargo test --release --test learn_calib calib_diag_write -- --ignored --exact --nocapture
```

112 files (`qkv`, `o`, `gate_up`, `down` per layer), 6,653,696 B in total; the layout exists for
every layer (`g0`–`g27`). Wall time 9,243.5 s for 35 chunks, 264 s per chunk. Layer 27's full-Gram
control against the diagonals:

| kind | `rel` |
|---|---:|
| `qkv` | 1.408e-6 |
| `o` | 2.057e-6 |
| `gate_up` | 1.056e-6 |
| `down` | 2.812e-6 |

The layout threshold is 1e-4; the diagonals reconstruct the full Grams 36× inside it. This
is calibration evidence only: a Gram is not a fit and not a pack.

## 3. Rate arithmetic: the ppm must be 1.18, not 1.15

`rank_for_bits(a, b, ppm, 32)` at `ppm = 1,150,000` gives `down`/`gate`/`up` rank 3424 and
`q`/`o` rank 2016, `k`/`v` rank 480. The packer's bit count
`32·(o·⌈r/32⌉ + r·⌈n/32⌉) + 16·(n + r + o)` then stores **1.14110 b/w** over the replaced linears,
below Q1's 1.15 floor. At `ppm = 1,180,000` the ranks are 3520 for `gate`/`up`/`down`, 2080 for
`q`/`o` and 512 for `k`/`v`:

| kind | shape | rank | stored b/w |
|---|---|---:|---:|
| `q`, `o` | 3584×3584 | 2080 | 1.17223 |
| `k`, `v` | 512×3584 | 512 | 1.18304 |
| `gate`, `up` | 18944×3584 | 3520 | 1.17409 |
| `down` | 3584×18944 | 3520 | 1.17409 |

Aggregate: **273,602,560 bits/layer, 957,608,960 B for 28 layers plus 196 section headers (6,272
B) = 957,615,232 B, 1.174036 b/w on 6,525,288,448 weights**. That is inside Q1's interval. A pack
at `APEIRON_NQ_BITS_PPM=1150000` would have missed the criterion by 0.009 b/w; the campaign command
below uses 1180000. Grade: `model` (the formula and `rank_for_bits` are source; the pack does not
exist to weigh).

The `o` fit's own print at 1.15M, `r 2016 b/w 1.1339`, is that row's rate, not the model's.

## 4. The fits: one projection passes, `down` refuses

Probe command (`probe.sh`, `APEIRON_NQ_LAYERS=0`, `APEIRON_NQ_KIND` per run):

```
APEIRON_NQ_MODEL=/workspace/models/Qwen2.5-7B-Instruct-f16.gguf \
APEIRON_NQ_CACHE=/workspace/models/q7b-cache APEIRON_NQ_GRAM_TAG=c6x29 \
APEIRON_NQ_TAG=-probe APEIRON_NQ_BITS_PPM=1150000 APEIRON_NQ_RELH=0 \
APEIRON_NQ_DENSE=0 APEIRON_THREADS=20 APEIRON_NQ_LAYERS=0 APEIRON_NQ_KIND=<kind> \
APEIRON_NQ_ITERS=<0|1> \
  cargo test --release --test learn_nanoquant nq_fit -- --ignored --exact --nocapture
```

| kind | T | wall | result |
|---|---:|---:|---|
| `o` | 1 | 18.3 s | rank 2016, 1.1339 b/w, `admm_loss 49671.18247` |
| `down` | 0 | 63.8 s | `factorize: Kernel` |
| `down` | 1 | 270.0 s | `factorize: Kernel` |

The first `down` failure was `Plane::build` refusing `n = 18,944 > MAX_INNER = 16,384`
(`src/engine/kern/limb.rs`). `MAX_INNER` bounds what the limb path accepts; a width past
`gemm_q8_0`'s own 512 blocks (16,384) already falls back to `matmat_q8act` on the same planes —
the same `Q8_0` contract, slower — so the accepted width is not that kernel's stack-array bound.
It moved to `1024·Q8_0_QK = 32,768`, with `inner_past_512_blocks_products` exercising `gemm_q32`,
`syrk_q32` and `rowdot_q32` at 18,944. The 63.8 s T=0 failure is fully explained by that build; the
T=1 failure after the raise is not, and at the time of the run the error collapsed every
`LimbError` into `NqError::Kernel`, so the failing call was not recorded. This change carries
`NqError::Kernel(LimbRefusal)` (shape, range or no kernel), so the next run prints which
refusal it was. The 18,944-wide products run on the `matmat_q8act` fallback in this probe.

Two tolerance changes in this change address the two remaining kernel calls in the diagnostic
path: `admm_loss` returns `INFINITY` on `LimbError::Range` instead of refusing the fit, for both
the `rowdot_q32` Gram diagonal and the prediction `gemm_q32`, and `export`'s column norms are summed
in f64 instead of through `rowdot_q32`. A scalar diagnostic and a norm cannot refuse a factor the
export can still write. Neither change has run on the 7B shape; the T=0 and T=1 rows above are
before them.

The 18.3 s `o` number is a console transcript from the box, not a preserved log; `probe.log` and
`probe1.log` hold only the `down` failures. The `down` wall times are in `probe1.log`.

## 5. Cost and the blocker

At the measured 270 s per `down`-shape iteration on 20 threads, the full T=1 pack costs about
3×270 + 2×18 + 2×3 ≈ 852 s per layer, **6.6 h for 28 layers, about `$1.32`** at `$0.2003/h`, plus
setup. Each extra outer iteration adds the same 6.6 h:

| T | wall | cost at `$0.2003/h` |
|---:|---:|---:|
| 1 | 6.6 h | `$1.32` |
| 10 | 66 h | `$13` |
| 30 | 199 h | `$40` |

The fit's loss at T=1 is 4.97e4, not a converged factor; the reference run is T=400. The measured
`o` probe at T=1 prints the loss the first iteration reaches, so T=1 is a shape test, not a quality
candidate; Q2 cannot be claimed from it.

Remaining vast.ai credit after destroying the box: **`$0.4537546793500411`**, no instances running.
That is 2.3 box-hours: it does not cover the 6.6 h T=1 pack plus a rerun of `down`, and it is far
from a quality-bearing T. The campaign waits on a top-up, or on the GPU limb path
(`src/gpu/limb`, the path the 8B v3 pack used) on a GPU instance: `src/learn/nanoquant/step.rs`'s
`DEV_INV_CUT` note measures 100 device-resident iterations of the blk.23 `ffn_down` fit at 2.4–2.6 s
on an RTX 5080, against 270 s per iteration here.

## 7. What this does not establish

- No `.nqf` beyond one `o` probe and no `model.nqp`; Q1 stays **partial**.
- No wikitext-2 PPL and no 0-shot suite; Q2 is untouched.
- No memory sample, no 200k context, no throughput; M1, T1 and T2 are untouched.
- The 18,944-wide limb path is exercised by a synthetic unit test, not by a completed 7B `down`
  fit. rustc, LLVM, the kernel ABI and the device remain outside every claim here.
