16: ## Purpose
17: 
18: Apeiron is the O(1)-primitive basis at fixed probe width with bounded callbacks and nonconstant key length,
19: evolved from hashtrinity; `fold/hashtrinity` is the naive predecessor. The basis is
20: `R[x]/(x^2 - sigma)`, `Cell<R>` with `Sigma` as a value in every executing signature, `Coord`
21: addressing correct per face, and the growable flat/spill `Table<K, V, H, N>` with transactional
22: checked-sizing and reservation refusal. Every executing face must refine the canonical object;
23: anything not rooted in it is not accepted. A judgment about the object is admissible only at its
24: stated evidence grade and scope, through an explicit link to the claimed property of its named
25: denotation: equal denotations preserve that property, and implementation, resource or performance
26: observations require their own stated model and evidence rather than following from functional
27: denotation alone. The canonical object is
28: `Apeiron.Table.{HMap,get,insertWith,build}` and
29: `Apeiron.Trichotomy.AnyRing.{RingCell,ringMul,ringNormForm}` with the extracted `Cell<i64>` word
30: bodies (`word_mul_denote`, `word_norm_denote`).
31: 
32: The fold crosses from hashtrinity into apeiron, and that crossover is the lineage; the precise
33: statement is in [programme direction](docs/direction.md#lineage-the-fold-crossover).

100: ## 2 · Lifecycle
101: 
102: Every nontrivial epic proceeds through five phases. The first three are sections of one committed
103: file per epic, `docs/epics/<slug>.md`, started from `docs/templates/epic.md`; `docs/README.md` indexes
104: every epic. A document parsed by a gate lives in `docs/contracts/` and is never merged or reformatted.
105: 
106: 1. **Intent** — the problem, why alternatives were rejected, the invariants, the measurable success
107:    condition, the non-goals.
108: 2. **Spec** — the contracts, the admissible domain and partiality, the Rust-to-Lean representation
109:    relation, the failure semantics, the evidence plan.
110: 3. **Plan** — the waves, files, owners, one gate command per task, and the negative control where
111:    soundness is at stake.
112: 4. **Implementation** — the smallest change that turns the named gate green, on the path the crate and proof build and run.
113: 5. **Verification** — run the gate and its control, record the result, then register the claim at its
114:    evidence grade.
115: 
116: An epic without a written intent, spec and plan is still design. Do not allocate tasks from it.

118: ## 3 · Work decomposition and collision discipline
119: 
120: `epic -> wave -> task`.
121: 
122: - A **wave** is a barrier: every gate green, with its negative control run, before the next opens.
123: - A **task** touches at most three files, carries one arc (scope, gate, control, grade), and is
124:   closed by one command's exit status, never by an agent saying so.
125: - A task that cannot run parallel to its siblings takes its own wave.
126: - **One in-progress owner per file.** Tasks in one wave touch disjoint files. Declare the owner in
127:   the plan. If a task needs a file another task owns, stop and sequence it; do not edit across the
128:   boundary.
129: - **Shared build products are lanes.** `proof/ApeironWord.lean`, `target/`, `proof/.lake/` and
130:   `proof/corpus/.lake/` each take one agent at a time. Do not mix incompatible Lean/Mathlib
131:   artifacts in a shared cache.
132: - **A branch and its worktree exist only for their task.** Work merges to `main`, the integration
133:   target, or is deleted; the worktree is removed with `git worktree remove`. Inventory with
134:   `git worktree list` and `git branch -vv` before starting and after closing, and prune stale
135:   records (`git worktree prune`). No branch or worktree outlives its task; one that does is a failed
136:   task, not a note.
137: - Do not run working-tree-mutating git commands (`stash`, `reset`, `checkout`, `restore`, `clean`).
138:   Preserve unrelated dirty work; a mutation control edits a throwaway copy, never the working tree.
139: - A task that needs conversation history to execute is not yet a task.

141: ### The dispatch loop
142: 
143: A red goal is worked by one loop, never by picking the easiest bounded task:
144: 
145: 1. **Sol ranks.** The lead asks Sol for the **highest-impact items** that move the goal, ordered by
146:    contribution *and difficulty*, hardest first. The ranking is written under
147:    `/home/socol/oc-tmp/escalation/` and is the dispatch order.
148: 2. **One lane per item.** Each item gets **one** lane, and no more lanes than the item's
149:    independent-file set: items that share a file (or a shared build product) **serialize** in Sol's
150:    order, never run in parallel. Never open the easy, bounded, safe, verification, corpus,
151:    instrument or documentation task while the goal's number is red; use spare capacity for
152:    independent verification, not invented parallel work.
153: 3. **Each lane closes on its gate and control**, on the path the crate builds, in an isolated copy.
154:    A lane returns the edited artefact, the exact gate output, the measurement and the decision — never
155:    a live write and never a commit. **A lane runs to completion inside one turn: it must not
156:    background its campaign, `sleep`, spawn a detached `runs.sh`/loop, or return "waiting" on a
157:    background waiter.** A lane that comes back without its numbers is not a lane; it is a stall the
158:    owner cannot distinguish from progress. The lead dispatches agents, not ad-hoc background shell
159:    campaigns, and follows them to their return.
160: 4. **The lead installs.** The lead applies the lane to the live tree, **re-runs the gate on the live
161:    tree**, and commits. A lane's green gate is not the live tree's green gate.
162: 5. **Measure, then board.** Run the averaged measurement, then update the board: the project
163:    check-in carrying the fresh numbers, and the task rows whose status changed. A checkpoint that reports
164:    no measured movement while the goal is red has failed and says so. **The board update is a field of
165:    the checkpoint lane's own return, not a step the lead performs from memory: the lane posts the
166:    check-in and moves the rows before it returns, and a return that carries numbers without the
167:    check-in and the moved rows has failed this step.** The per-cycle trigger is the operator pulse
168:    (`/home/socol/oc-tmp/bin/pool-ping.sh`); with it off, the board is stale until the next lane posts
169:    it — the cadence is the pulse, the content is the lane. The `commit-msg` hook enforces a board row
170:    per commit only; it does not force a per-cycle check-in.
171: 
172: Enforced at exactly two points: the operator pulse (`/home/socol/oc-tmp/bin/pool-ping.sh`) fires the
173: checklist and fails a checkpoint with no measured movement; and the per-commit board declaration
174: (`.githooks/commit-msg`, `tools/hooks/lane.py`) refuses a commit naming no row. The ordering rule —
175: hardest first — has **no** mechanical enforcer: it is owner direction, and a dispatch that inverts it
176: is a failure the lead owns.

182: epic closure. Existing short IDs remain historical aliases.

199: ## 3a · Dispatch priority
200: 
201: Order dispatch by contribution to the goal and by difficulty, never by dispatchability.
202: 
203: - The question is which task moves the programme outcome most and is hardest to do — not which
204:   task is bounded, well-specified, or likely to return green. A body of easy, safe, locally-green
205:   work (control registration, citation repair, splits, documentation sweeps) is not progress while
206:   the governing outcome is an open quantitative gate; it is avoidance, and it is not a reason to
207:   open a lane.
208: - Work each goal's written dependencies in order. A goal whose dependency is open gets no lane.
209:   **Penglai and webfold are downstream of the apeiron core and are frozen until apeiron beats
210:   hashtrinity *and* is formally verified** — i.e. G1 acceptance green (`full_acceptance=true`) and
211:   the real-source extraction with its refinement proved under the closed axiom cone. No penglai or
212:   webfold lane opens before that condition holds. Penglai's water frame rate and webfold's parser
213:   both ride the apeiron core; working them first is the same avoidance as hygiene.
214: - When a goal's gap is a measured number — a failing ratio, a frame rate, a latency — the lane that
215:   attacks that number outranks every hygiene task, and its first task is to reproduce the number on
216:   the current source. A recorded number is stale until re-measured; a stale number is not a status.
217: - Rank by expected contribution, then by difficulty. The hardest high-contribution task is
218:   dispatched before the easiest, however many lanes it needs.
219: 
220: - **Subsume the empirical best before deriving.** Empiricism and formalism are two sides of one
221:   coin: if an empirically better solution exists for a role, **subsume it first and formalize the
222:   subsumption**; never iterate from an obviously inferior primitive. The empirical side selects the
223:   base — the measured winner becomes the working artifact, on the measured path from step one; the
224:   formal side certifies that same artifact — the refinement targets the subsumed body. A
225:   formalization of a losing implementation is a certified loss; an unproved winner is an unverified
226:   gain. **Every dispatch names the empirically best known solution for its role by repository,
227:   revision and digest, and records `subsumed`, or `not-subsumable` with the exact reason and the
228:   search command and its output; a new primitive with an unstated or unexplained absence is
229:   refused.** Corollary: a lane whose base is a structure the measured winner does not pay is not an
230:   optimization but a tax — name the base and its measured ratio first. **Enforcer: the
231:   dispatch-admission `subsume` field (MISSING until built; until then this rule is review-enforced
232:   only and is recorded as such, not as acceptance).** Worked example: the empirically best counting
233:   structure is `../fold/hashtrinity` (pinned `Cargo.toml:76-80`, rev `4cc14471`); it must be
234:   subsumed and proved, not re-derived, and the generic `Table` (`src/table.rs`) is the inferior
235:   primitive — not a valid base for a count-face optimization.
236: 
237: - **The incumbent's evidence is pinned, not regenerated.** Read `../fold/hashtrinity` at the G1
238:   revision `4cc14471` (`src/lib.rs` sha256 `f8c8fd12fc2b7a69…`; fold HEAD `d497161f`'s `lib.rs` is
239:   `5bc1c9f48ef0bb17…`, a **different** file — do not mix the two) and its monomorphized disassembly,
240:   already emitted, at `/home/socol/oc-tmp/ht-llvm/`: `full.asm` sha256 `b68a950e375e5516…`, `ap.asm`
241:   `2841d4faa631e537…`, `disasm.txt` `61bc3365ac8c71d5…`, with the instruction-level work order in

248: ## 4 · Definition of done
249: 
250: A task closes on its focused gate and control, completed within its §10 wall-clock budget; a
251: timeout is not closure. A wave requires every child plus the shared gates.
252: An epic closes only when every row of its exit table is green on the same source/tool identity;
253: missing gates, witnesses or evidence keep it open. `docs/plan.md` owns the epic exits;
254: Historical completion records are not fresh acceptance.
255: Record inapplicability with its excluded population and reason, never because a gate is difficult.

258: 
259: | Pillar | Obligations |
260: |---|---|
261: | Primary artifact | 1, 3: build and run path and real-source extraction |
262: | Non-vacuous contracts | 2: domain, joint witnesses, initialization and preservation |
263: | Mathematical attribution | 4, 5: exact authority, refinement and closed axiom cone |
264: | Falsifiable verification | 6, 7: positives and baseline/red/restore controls |

269: 1. **Build and run path.** The change is on the path the crate and proof actually build and run; there is no separate production, reference or mock path. No stub, parallel copy or dead code presented as complete.
270: 2. **Explicit admissible domain and partiality.** Total, `Option`/`Result`, checked, or panicking is
271:    stated. Every claimed `Pre`/`WellFormed` domain has a checked witness term or `#guard` for the
272:    joint hypotheses at the claimed types, not separate incompatible witnesses. Require initialization
273:    from the actual constructor, preservation, and successful/refusing branch witnesses for partial
274:    operations. A model witness does not refine a Rust constructor. No silent domain reduction or
275:    infallible signature over an operation that can lose bits.
276: 3. **Actual Rust extraction where a Rust claim is made.** The Aeneas/Charon extraction includes the
277:    real source by `#[path]` and calls the real body; a wrapper may fix a type, not restate the
278:    formula.
279: 4. **Lean theorem link.** The representation relation names the exact canonical definition or
280:    theorem it refines. Generic mathematics lives in the pinned canonical corpus, navigated at
281:    `../sanguine-apeiron/proof/Apeiron/`; its audits are `Audit.lean` and `AuditCarrier.lean`.
282:    Rust representation theorems live in `proof/corpus/`, audited by `AxiomAudit.lean`.
283:    Record the resolved corpus revision; a sibling path or `@grade` alone proves nothing.
284: 
285:    **Search the lineage and the sibling repos before commissioning a primitive.** A primitive this
286:    tree lacks very often already exists — most likely in the older corpus (`../sanguine`,
287:    `../sanguine-apeiron`), sometimes solved in a different sibling repo entirely. That form is a
288:    **port with a named target**, not a new derivation, and the spec phase records the search: the
289:    declaration found, its revision and digest, and what the port must add. Only absence everywhere
290:    authorizes making one — and then the spec says so explicitly, because "we made it" is a claim
291:    about prior art as much as about code. The search is a command over the loaded in-tree lineage plus
292:    `~/Workspace/*` (fleet brief §9 names the repositories), not a recollection.
293: 
294:    **Use a search tool that works here.** `find` is shadowed by a broken shim on this box
295:    (`/home/socol/.local/bin/find`, findutils 4.4.2): it exits 0 and returns **nothing** on directories
296:    that plainly hold files, so a `find`-based absence check is unsound and has already produced one
297:    false "the corpus has 0 Lean files" claim. Use `rg --files`, `ls -R`, or a shell glob, and state the
298:    command in a claim of absence. `grep` is likewise shadowed/mangling; `rg` is the working tool.

300:     `proof/corpus/AxiomAudit.lean` `#audit`s each headline and throws on anything outside

304:     `tools/slang/zero_axioms.py`; `propext`, `Classical.choice`, `Quot.sound`, `noncomputable` and
305:     quotient-based representations such as `Finset` and `ZMod` are rejected there. The Rust/Aeneas
306:     bridge and the canonical corpus retain the closed cone above.
307: 6. **Positive tests.** `cargo test` covers the nominal path and the boundary cases that the contract
308:    names.
309: 7. **Mutation control.** A mutation of the real source (or the generated kernel) in a throwaway copy
310:    must turn the proof or test red; restoring it must pass. A check that cannot fail has no weight.
311: 8. **Source and tool digests.** Record the sha256 of the sources the evidence binds to, and the
312:    Aeneas/Charon/Lean/Mathlib revisions. Evidence from a dirty tree is attributed to those digests,
313:    not to HEAD alone.
314: 9. **Rust gates.** `cargo test`, `cargo clippy` and `cargo fmt` as in §6 pass.

316:     and its output was read. Name the machine, the metric and the interval; before and after.
317:     **Average across runs.** Report the mean over at least three runs with the observed spread; a
318:     single run is a sample, not a result. A pass-count or ratio that moved within the spread
319:     already measured on unchanged code is not a change and is not reported as one. The
320:     repeated-run protocol belongs to the harness, not to the reader's patience.
321: 11. **Trust-boundary statement.** State what the claim does not cover: rustc/LLVM codegen, the
322:      kernel ABI, GPU/SPIR-V, the `unsafe` container, or any layer the evidence does not reach.

408: guard) are forbidden in committed proofs and in an agent's runs; a reduction that needs them is
409: inconclusive, not a proof, and a job that exhausts the cap is a failure of the run, not a red gate.

411: **Every Rust command runs under the same bound.** `cargo build|test|run|clippy|rustc`, every
412: measurement campaign (the `examples/reg1` campaign was removed in `c9a2d0c`), and every lane's
413: build or test step run under
414: `systemd-run --user --scope -p MemoryMax=<cap> -p MemorySwapMax=0` with a `timeout` carrying the §10
415: budget; a lane that spawns a build without the cap is not admitted and its result is not evidence. The
416: bound exists because an uncapped workspace build at 16 codegen units is 0.5–2.7 GB: twenty concurrent
417: lanes drove this 62 GB box to a **54 GB memory peak plus 50 GB swap inside one terminal cgroup**, with
418: no OOM-kill and no panic — the kernel stopped scheduling the cgroup, which presents as a dead terminal.
419: A build is not exempt because it is short.
420: 
421: **Concurrency is capped, not aspirational.** At most **eight** build-bearing lanes run at once on this
422: box; a ninth waits on `flock /tmp/opencode/apeiron-lane.lock` or on a finished lane's return, and the
423: sum of the declared caps stays under half of RAM. Twelve to twenty concurrent workspace builds is the
424: ceiling being exceeded, not a width being achieved — a fan-out wider than the file-disjoint set pays
425: contention, not throughput, and it is what crashed the terminals. **A measurement is averaged, never
426: refused for a busy box.** A contended run is a valid measurement when it is repeated: run at least
427: five paired runs and report the per-pair mean with the observed spread. Contention is answered with
428: more runs, not with a quiet window, a refusal, or a guard override that prints a single contended
429: sample as a result. Do not hold an accepted campaign behind a quiesced box.

443: ## 8 · Writing
444: 
445: - **No anthropomorphic or story prose.** State mechanism and evidence. Do not write that a table
446:   "wants", a map "refuses", a dial "decides", or a crate "believes". Name the value, the operation
447:   and the measured effect.
448: - **Standard mathematical language, with attribution.** Name every mathematical object by its most
449:   common standard term and notation (`R[x]/(x²−σ)`; elliptic `σ<0`, parabolic `σ=0`, hyperbolic
450:   `σ>0`; norm form, idempotent, zero divisor) — never by a project or legacy coinage. For a borrowed
451:   object cite the originator(s) first, then the reference (norm form: Gauss, *Disquisitiones
452:   Arithmeticae* (1801); dual numbers: Clifford (1873); split-complex numbers: Cockle (1848); softmax:
453:   Boltzmann (1877) and Gibbs (1902), Bridle (1990) for the name). The reference is retrieved and read
454:   before it is called evidence; a citation alone is a pointer (§9.3).
455: - Present tense for what is; past tense for what happened. No dates in prose; git has them.
456: - Lowest word count that keeps every path, hash, identifier and number.
457: - Tables and bullets over paragraphs. A qualifier belongs in the sentence that needs it.
458: - Do not narrate a plan code (`E1`, `Wave 2`) in a durable document. Describe the change in terms
459:   that resolve to the tree: paths, gate names, theorem names.
460: - A number from a document is a hypothesis until the command is re-run.
461: - **State per-function complexity where it is not O(1).** A function whose temporal cost or spatial
462:   footprint is not O(1), or is not immediate from its type, carries a comment at its definition: the
463:   temporal and spatial complexity, the measure they are counted in (comparisons, allocations, bytes,
464:   words, bytes copied), and the derivation (the recurrence or loop and why it closes). A complexity
465:   figure is a claim like any other: it names the recurrence or the command, never a bare big-O.
466:   Trivial O(1) accessors, projections and constructors carry none.
